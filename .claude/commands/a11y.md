# /a11y — Accessibility Audit

Full axe-core accessibility audit across all FlowTask views via Playwright. Reports violations by severity with per-page breakdowns and fix suggestions.

## Steps

### 1. Create the team

Create a team called `a11y-audit`.

### 2. Ensure dev servers are running

Check whether the backend (port 3001) and frontend (port 5173) are already running:

```bash
PATH="/Users/zain/.npm-global/n/versions/node/22.18.0/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:$PATH"
lsof -ti:3001,5173
```

If either server is not running, start both from `/Users/zain/myFiles/claude-test/flowtask`:

```bash
PATH="/Users/zain/.npm-global/n/versions/node/22.18.0/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:$PATH"
pnpm dev
```

Wait until both servers are confirmed listening before spawning the audit agent.

### 3. Spawn the auditor agent

Spawn one agent named `"auditor"` with:
- `model: "sonnet"`
- `mode: "bypassPermissions"`
- `max_turns: 20`

Set `PATH="/Users/zain/.npm-global/n/versions/node/22.18.0/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:$PATH"` in all bash commands.

All commands run from `/Users/zain/myFiles/claude-test/flowtask/`.

---

The auditor agent should:

#### Step A: Check/install dependencies

```bash
cd /Users/zain/myFiles/claude-test/flowtask
PATH="/Users/zain/.npm-global/n/versions/node/22.18.0/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:$PATH"
node -e "require('@axe-core/playwright')" 2>/dev/null && echo "axe-core/playwright OK" || pnpm add -D @axe-core/playwright
```

#### Step B: Write and run a Node.js audit script

Write a script to `/tmp/a11y-audit.mjs` that uses Playwright + @axe-core/playwright to audit all views. The script should:

1. Launch Chromium (headless)
2. Navigate to `http://localhost:5173`
3. For each of the following **pages/states**, run an axe accessibility check and collect all violations:

   | # | Page/State | How to reach |
   |---|-----------|--------------|
   | 1 | List view (default) | Navigate to `/`, wait for task list |
   | 2 | Kanban view | Click Kanban view button/tab |
   | 3 | Calendar view | Click Calendar view button/tab |
   | 4 | Task creation modal | Click the "New Task" or "+" button to open the form |
   | 5 | Quick Capture dialog | Press `Ctrl+K` to open |
   | 6 | Task detail panel | Click on any task to open its detail view |
   | 7 | Settings panel | Open settings (gear icon or settings link, if exists) |

4. For each page/state:
   - Run `new AxeBuilder({ page }).analyze()`
   - Capture violations array
   - Take a screenshot saved to `/tmp/a11y-<pagename>.png` if any **critical** or **serious** violations are found
   - Record: page name, violation count by impact level (critical/serious/moderate/minor), violation details (id, description, impact, nodes affected, WCAG tags)

5. After all pages are audited, compute:
   - **Total violations** across all pages, grouped by severity
   - **Per-page breakdown table**
   - **Top 5 most impactful violations** (highest impact + most pages affected), each with: WCAG rule ID, description, impact level, affected element selector(s), suggested fix

Run the script:

```bash
PATH="/Users/zain/.npm-global/n/versions/node/22.18.0/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:$PATH"
node /tmp/a11y-audit.mjs 2>&1
```

#### Step C: Format and send report

Send the audit results to `team-lead` as a markdown message with these sections:

```
### Accessibility Audit Report

#### Summary
| Severity | Total Violations |
|----------|-----------------|
| Critical | N |
| Serious  | N |
| Moderate | N |
| Minor    | N |
| **Total**| **N** |

#### Per-Page Breakdown
| Page | Critical | Serious | Moderate | Minor | Screenshots |
|------|----------|---------|----------|-------|-------------|
| List view | 0 | 2 | 3 | 1 | — |
| Kanban view | 1 | 0 | 2 | 0 | /tmp/a11y-kanban.png |
| ...  | ... | ... | ... | ... | ... |

#### Top 5 Most Impactful Violations
1. **[WCAG rule ID]** — [description]
   - Impact: Critical
   - Affected pages: List view, Kanban view
   - Element: `button.close-btn` (missing accessible name)
   - Fix: Add `aria-label` or visible text content to the button

2. ...
```

If any page/state could not be opened or tested, note it with `N/A - [reason]`.

### 4. Report and clean up

Team lead displays the auditor's full report to the user, highlighting any critical violations.

Send `shutdown_request` to the auditor agent, then call `TeamDelete` to clean up the `a11y-audit` team.
